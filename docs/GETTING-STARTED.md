# Getting started

These steps take a new clone to an active run and a first game note.
They use the shipped command-line tool only for vault maintenance and demo content.
Creating campaigns, parties, and runs happens in the Table Tools home view.

1. Clone the repository and enter the vault directory.

   ```text
   git clone https://github.com/jakrog01/RPGVault.git
   cd RPGVault
   ```

   Cloning creates the complete vault, including `_system/`, `_local/`, content-root folders, and the shipped Obsidian configuration.

2. Open the `RPGVault` folder as a vault in Obsidian.

   Opening does not ask the CLI to create notes; Obsidian reads the existing vault files.

3. In Obsidian, enable community plugins and enable `templater-obsidian`, `calendarium`, and `table-tools`.

   The template contributes those ids through `.obsidian/community-plugins.json`; Obsidian stores its application settings under `.obsidian/`.

4. Check the shipped vault before changing it.

   ```text
   node _system/bin/rpgvault.mjs doctor
   ```

   `doctor` reads the vault and prints `RPGVault doctor: clean (<version>)` when its checks pass; it does not create content.

5. Install the example material and look through its campaigns, parties, runs, library, and calendar notes in Obsidian.

   ```text
   node _system/bin/rpgvault.mjs demo install
   ```

   This copies the shipped demo files into content roots and reports `demo installed`.

6. Remove the example when you are finished studying it.

   ```text
   node _system/bin/rpgvault.mjs demo remove
   ```

   This deletes only Markdown notes whose frontmatter has `origin: demo`, removes emptied demo directories, and reports how many demo notes it removed.

7. Open **Table Tools: Home** from the ribbon icon or command palette, then choose **New campaign**.

   The form creates a campaign folder and `Campaign.md` from the local template when present, otherwise the shipped template.

8. In the same home view choose **New party**, then choose **New run** and select the campaign and party.

   A run creates its `Run.md`, `State.md`, and `World Day.md` records in the new run folder.

9. Leave **Make active** enabled when creating the run, or use **Make active** on its card afterward.

   This rewrites the root `Active.md` pointer so Table Tools, combat, and the assistant use that run context.

10. Create your first Markdown note in the active run folder and link it to the campaign or party where useful.

    This is ordinary vault content under `Runs/`; it is not generated by `doctor` or by an update.
